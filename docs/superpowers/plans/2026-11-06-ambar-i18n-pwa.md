# Ámbar i18n + PWA adaptativa + modo solo menú — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** App pública en 10 idiomas (con RTL árabe), PWA adaptada a iOS/Android/tablet/escritorio, e interruptor admin para desactivar pedidos.

**Architecture:** Diccionarios TS tipados contra `es.ts` + `I18nProvider` (contexto) que fija `lang`/`dir` en `<html>`. Contenido de BD traducido en columnas `i18n jsonb` y `settings.data.i18n`, leído con `localized()`. PWA: manifest ampliado, splash iOS generados, CSS con propiedades lógicas y áreas seguras.

**Tech Stack:** React 19, Vite 8, vite-plugin-pwa, motion, Supabase, vitest, Python/Pillow.

**Spec:** `docs/superpowers/specs/2026-11-06-ambar-i18n-pwa-design.md`

## Global Constraints

- Idiomas y códigos: `es en de ru pt it fr zh ko ar`; `ar` es `dir="rtl"`. Clave de almacenamiento `ambar:lang`.
- El panel admin sigue en español; el mensaje de WhatsApp sigue en español + línea `Idioma del cliente: <nombre en español>`.
- Precios siempre `formatCOP` (`$35.000`), dígitos occidentales en todos los idiomas.
- Nada de secretos ni la clave admin en el repo; `SUPABASE_ACCESS_TOKEN` solo por entorno.
- Inputs con `font-size >= 16px`.
- `ordering.enabled` ausente = activo.

## Review Focus

- Idioma guardado inválido en `localStorage` (p. ej. `"xx"` de una versión futura) → se ignora y se detecta, no pantalla rota (test en Task 1).
- Traducción vacía `""` en BD → muestra español, no un hueco (test `localized` en Task 1).
- Cambiar a árabe y volver a español → `dir` vuelve a `ltr` y la barra lateral vuelve a la izquierda (Playwright Task 4).
- Carrito con productos cuando el admin desactiva pedidos → no se pierde, no se puede enviar, mensaje claro (Task 5 test + SQL).
- `admin_set_ordering` no debe borrar el resto de `settings` (SQL Task 2).
